# เจอบั๊กแล้วเพิ่ม test ยังไง

คู่มือสำหรับตัวเองตอนกลับมาทำต่อ

---

## ขั้นตอน 4 ข้อ

```
1. หาให้เจอว่าพังชั้นไหน
2. เขียน test ที่แดงก่อน       ← ห้ามข้าม
3. แก้โค้ด
4. รัน test จนเขียว
```

**ข้อ 2 สำคัญที่สุด** ถ้าเขียน test หลังแก้โค้ดเสร็จแล้ว จะไม่มีทางรู้ว่า test นั้น
จับบั๊กได้จริงหรือแค่ผ่านเฉย ๆ เคยเจอมาแล้วตอนใส่ `"5"` เป็นค่าต้องห้าม
แล้วมันไปตรงกับชื่อ `cache-prod-005` — test แดงทั้งที่ระบบทำงานถูก

---

## ขั้นที่ 1: หาว่าพังชั้นไหน

ไล่ตามลำดับที่ข้อมูลไหลผ่าน แต่ละจุดมีวิธีดูของจริง

| ชั้น | ดูยังไง |
|:---|:---|
| อ่านไฟล์ | `python3 -c "from readers import read_file; print(read_file('ไฟล์').text[:800])"` |
| หั่น chunk | เปิด Qdrant dashboard `localhost:6333/dashboard` แล้วดู payload |
| ค้นหา | ดู score กับ heading ในบัตรอ้างอิงบนหน้าเว็บ |
| SQL | กด "ดูคำสั่งที่ใช้คำนวณ" บนหน้าเว็บ |
| คำตอบ | DevTools → Network → `/query` → Response |

**หลักการ:** ดูข้อมูลจริงที่ไหลผ่านแต่ละชั้น อย่าเดาจากอาการ

เคยเสียเวลาเดาผิด 2 รอบตอนคำตอบขาดกลางประโยค (คิดว่าเป็น `temperature` แล้ว
คิดว่าเป็น `num_predict`) สุดท้ายเปิด Qdrant dashboard ดู payload แล้วเจอทันที
ว่า chunk ถูกตัดที่ตัวอักษรที่ 800

## ขั้นที่ 2: เลือกไฟล์

| บั๊กอยู่ที่ | ไฟล์ | ต้องรัน LLM ไหม |
|:---|:---|:---|
| อ่านไฟล์ผิด (PDF/Excel/CSV/txt) | `test_readers.py` | ไม่ |
| หั่นเอกสารผิด | `test_chunking.py` | ไม่ |
| ภาษาไทย / Unicode | `test_normalize.py` | ไม่ |
| SQL ผิดรูปแบบ | `test_sql_safety.py` | ไม่ |
| เขียนคำถามใหม่ผิด | `test_rewrite.py` | ไม่ |
| **ตอบผิด แต่ยังไม่รู้สาเหตุ** | `test_sql_e2e.py` | ใช่ |

**ถ้าไม่แน่ใจ** ให้เพิ่มใน `test_sql_e2e.py` ก่อน (ง่ายสุด เติมบรรทัดเดียว)
แล้วค่อยย้ายไปไฟล์ที่ตรงกว่าเมื่อรู้สาเหตุแล้ว

**บั๊กสำคัญควรมี test 2 ที่** — ชั้นเร็วบอกว่าพังตรงไหน ชั้น e2e บอกว่าผลลัพธ์ถูกไหม
เช่นบั๊ก `COUNT(*) OVER ()` มีทั้งใน `test_sql_safety.py` และ `test_sql_e2e.py`

## ขั้นที่ 3: เขียน test

### แบบที่ 1 — เติมใน e2e (ง่ายสุด)

เปิด `test_sql_e2e.py` แล้วเติมใน `CASES`:

```python
CASES = [
    ...(
        "เดือนไหนใช้จ่ายมากที่สุด",  # คำถาม
        ["มีนาคม", "53270"],  # ค่าที่ต้องปรากฏ
        [],  # ค่าที่ต้องไม่ปรากฏ (คำตอบผิดเดิม)
        "GROUP BY เดือนแล้วหาค่าสูงสุด",  # คำอธิบาย โผล่ตอน test แดง
    ),
]
```

จบ ไม่ต้องเขียนฟังก์ชัน `@parametrize` สร้าง test ให้เอง

⚠️ **ระวังค่าที่สั้นเกินไป** ในช่อง "ต้องไม่ปรากฏ" — เช่น `"5"` จะไปตรงกับ
`cache-prod-005` ทำให้ test แดงทั้งที่ระบบถูก ใช้ค่าที่ยาวพอจะไม่ชนกับอย่างอื่น

### แบบที่ 2 — เขียน test ใหม่ในชั้นเร็ว

```python
def test_ชื่อที่บอกว่าทดสอบอะไร():
    """
    บั๊กจริง: อธิบายอาการที่เจอ และตัวเลข/ข้อความจริงที่ผิด
    """
    ผลลัพธ์ = ฟังก์ชันที่ทดสอบ(ข้อมูลที่ทำให้พัง)
    assert เงื่อนไขที่ควรเป็น
```

**docstring สำคัญ** — เขียนอาการจริงพร้อมตัวเลข เพราะอีก 3 เดือนกลับมาอ่าน
จะไม่มีทางจำได้ว่า test นี้กันอะไร

### แบบที่ 3 — หลายเคสในรูปแบบเดียวกัน

```python
@pytest.mark.parametrize(
    "input,expected",
    [
        ("เคส 1", "ผลที่ควรได้ 1"),
        ("เคส 2", "ผลที่ควรได้ 2"),
    ],
)
def test_ชื่อ(input, expected):
    assert ฟังก์ชัน(input) == expected
```

### แบบที่ 4 — ต้องใช้ไฟล์

**สร้างไฟล์เองใน `tmp_path` เสมอ** อย่าอ้างถึงไฟล์ใน vault
เพราะ test ต้องรันได้บนเครื่องคนอื่นที่ clone repo ไป

```python
def test_อ่านไฟล์แปลก(self, tmp_path):
    f = tmp_path / "test.csv"
    f.write_text("a,b\n1,2", encoding="utf-8")
    d = read_file(f)
    assert "..." in d.text
```

## ขั้นที่ 4: รัน

```bash
pytest -m "not llm"          # เร็ว 1-2 วินาที รันทุกครั้งที่แก้โค้ด
pytest                       # เต็ม 2-4 นาที รันหลังแก้ prompt
pytest tests/test_readers.py -v       # เฉพาะไฟล์
pytest -k "chunking" -v               # เฉพาะ test ที่ชื่อมีคำนี้
pytest --lf                           # เฉพาะที่แดงรอบก่อน
```

## ข้อควรระวังที่เจอมาแล้ว

**ชื่อฟังก์ชันใช้ ascii เท่านั้น**
ภาษาไทยมีอักขระที่หน้าตาเหมือนกันแต่คนละ codepoint (`คำ` กับ `คํา`)
ทำให้ pytest หา parameter ไม่เจอ ชื่อ test ใช้อังกฤษ ส่วนข้อความใน
`assert` และ docstring ใช้ไทยได้

**อย่าให้ test พึ่งพากัน**
แต่ละ test ต้องรันเดี่ยว ๆ ได้ ถ้า test A ต้องรันก่อน test B จะพังเมื่อรันสลับลำดับ

**optional dependency ใช้ importorskip**
```python
openpyxl = pytest.importorskip("openpyxl")
```
เครื่องที่ไม่ได้ลง library จะข้าม แทนที่จะแดง

**test ที่ต้องใช้ database ให้ skip ถ้าไม่มี**
ใช้ fixture `db_conn` หรือ `server_table` จาก `conftest.py`
มันจะ skip อัตโนมัติถ้าต่อไม่ได้

## เมื่อแก้บั๊กแล้ว ทำ 3 อย่าง

| ทำอะไร | จุดประสงค์ |
|:---|:---|
| เพิ่มตัวอย่างใน prompt | ลดโอกาสเกิดซ้ำ |
| เพิ่มตัวตรวจ/ซ่อมในโค้ด | จับได้เมื่อยังเกิด |
| **เพิ่ม test** | รู้ทันทีถ้ากลับมาอีก |

ข้อสุดท้ายสำคัญที่สุด เพราะเป็นตัวเดียวที่บอกได้ว่าสองข้อแรกยังทำงานอยู่
หลังจากแก้อย่างอื่นไปแล้ว

prompt เป็นการ "ขอ" ให้ LLM ทำตาม โค้ดตรวจสอบเป็นการ "บังคับ"
ทั้งคู่ยังพังได้ ถ้าไม่มี test คอยเฝ้า
